# Public API environment configuration

Date: 9 October 2026. Development branch: `dev`. The user requested frontend API addresses as environment settings instead of manually editing build output.

The existing network loader now uses this precedence: direct `VITE_API_ORIGIN` during Vite development, then the complete `VITE_API_PRODUCTION` / `VITE_API_TESTNET` pair, then the existing network file for compatibility/local proxy mode. Both deployed URLs use the existing HTTPS-origin validator. Incomplete or invalid configured pairs reject startup rather than silently using another service.

The change adds no dependency, API model, backend setting or generated-file script. `.env.production.example` documents the default static build; `.env.testnet.example` documents `npm run build -- --mode testnet`. Vite embeds the public values, so static deployments require a new build/upload after edits. Network selection and its separate CSRF keys remain unchanged; a new browser still defaults to Production.

## Verification

- The new unit regressions failed before the loader change: one precedence failure and seven incomplete/invalid configuration failures. They passed afterward.
- `npm run verify` passed lint, Vue/TypeScript and 138 tests across 30 files. `npm run format:check` passed.
- The default `npm run build` passed. A separate `--mode testnet` build with synthetic HTTPS API origins also passed.
- Existing `tests/e2e/networks.spec.ts` passed all four desktop/mobile browser cases using HTTP fixtures.
- A compiled-build smoke check ran in desktop/mobile Chromium against an owned loopback preview. With `networks.json` still containing local mode, the compiled app called the env-configured mock APIs, switched networks, retained selection after reload, opened `/account` and `/docs` directly and made no network-file request.
- Core `npm run docs:check` passed after updating the development and operations runbooks. Generated product documentation was unchanged.

Browser checks used synthetic API responses; no real account login, payment or chain write occurred. Netlify/Hetzner were not provisioned or deployed. Backend/native/provider suites were not rerun for this frontend routing change. A previous immutable release packet does not qualify these new source commits.
