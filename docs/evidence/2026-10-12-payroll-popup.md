# Payroll popup and workspace heading cleanup

The user requested removal of the visible Workspace overview and Payroll headings, a plus icon opening an Add payroll popup, a payroll help icon and committing/pushing all changes including earlier work. This follows the authorized Decide/Works toolbar and native-dialog pattern. The overview retains its accessible region name and navigation entry; test callers use the region for readiness.

Payroll creation moves out of the list into a native modal. Active administrators can prepare a draft; authorized signing, installed commit permissions and the deployment compatibility/code pin remain required to submit. Member selection reuses the scoped, paginated public-profile/member loader, accepts only active members and rejects foreign DAO records. Metadata outages leave existing schedules readable. Recipient state is separate from Works contributors and amounts.

The preceding whole-token preference also applies here: the amount starts empty, accepts positive whole tokens without rounding, shows the treasury symbol and an exact integer total, and requires acknowledgement of the recipient, installments and total. Draft edits invalidate acknowledgement. Contract limits remain 1–12 installments and 1–31 days between payments, with a first due date within 31 days and a final due date within uint32. The field retains explicitly labelled UTC semantics. The popup preserves drafts on cancellation/failure, prevents pending editing/dismissal and clears submitted amounts/recipient on confirmed success. Settlement, pauses, existing approved liabilities, contract permissions and deployment pins are unchanged.

The initial browser regression failed on the still-visible Workspace overview heading. New input-helper tests initially failed because the helper did not exist. Unit cases cover exact conversions, ambiguous/invalid syntax, invalid term lengths/frequencies, individual/aggregate overflow, amounts beyond Number's safe integer range and date bounds. Browser cases exercise both viewports, keyboard focus restoration, accessibility, readable recipients, inactive-member exclusion, total/acknowledgement changes, visitor/non-admin restrictions, signed canonical payroll encoding, code-pin blocking, failed retry, pending state and foreign/member-read failures. Existing paid/native callers now open the popup and explicitly choose and acknowledge a whole-token installment.

Local verification passed: `npm run verify` completed lint, strict Vue/TypeScript and all **327 tests across 54 unit files**; `npm run build -- --mode testnet` completed with exit 0, retaining the existing large-chunk warning. All **22 Payroll/Works** desktop/Pixel 7 browser cases and **6 overview** cases passed. The custom `node tools/check-access.mjs` assertions passed for stale DAO data, private/public switches, inactive administrators, reviewer rules, module grants and unmounted uploads. Touched-file Prettier and whitespace checks passed after formatting the new spec.

The signed payroll regression uses a disposable real vault, validates login/instruction signatures and decodes the canonical ABI: recipient 2, **10.0000 TLOS**, three installments, seven days between payments and the chosen UTC first due time. It verifies blocked submission against an unverified deployment, amount/total rejection, retry preservation, pending dismissal/edit blocking and confirmed draft clearing. API/relay responses are synthetic; this establishes browser signing and encoding, not a native payroll settlement or live custody qualification. The paid/native end-to-end suite was updated but not rerun, and no live payroll commitment or payout was made.

All three Daclify worktrees were clean at the start. Earlier changes were already pushed; clean core/modules checkouts were fast-forwarded to their current origin/dev. This frontend change retains their pinned public SDKs (core 0.15.0-alpha.7, modules 0.10.0-alpha.14). Frontend 0.15.0-alpha.9 is the tested candidate. Publication results follow after the final public checks.
