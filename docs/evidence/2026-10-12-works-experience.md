# Works proposals and services experience

Requested: follow Decide’s toolbar/list/popup layout; replace proposal document and contributor ID inputs; put a help icon beside plus; provide a filtered work list; explain service listings versus project proposals.

Frontend 0.14.0-alpha.14 consumes unchanged core 0.14.0-alpha.5 and modules 0.10.0-alpha.5. Work proposals and Member services have separate accessible tabs. Both use one native proposal dialog; service selection preselects its active provider without silently choosing the service listing as the work specification. Active DAO membership permits preparation; existing signer/module/code/action checks still govern submission.

The document label helper is reused by Elections and Works and never parses encrypted metadata for public display. Proposal, milestone evidence and review selectors pin the selected record’s document identifier and version. Active contributor choices use DAO-scoped public profiles, native wallets or stable member labels. Content and names check the complete DAO reference; late responses are discarded on account/DAO/module change. Optional metadata reads are separate from module/treasury/governance state, so failures retain the work list with reference labels and retries. Payments retain integer conversions and the contract’s 1–16 positive milestone bound.

Search, status, contributor and agreement filters apply together to loaded projects; pagination appends additional records. Distinct filtered/empty states, counts and readable cards retain consent, funding, independent review, cancellation and settlement actions. No API, database, contract or authority changes are included.

Local verification passed: `npm run verify` completed lint, strict Vue/TypeScript and all 303 tests in 48 unit files; 12 Works Playwright checks passed across desktop Chromium and Pixel 7. They cover filter intersections/reset, named active contributors, exact document versions, private-title isolation, service-provider selection, document/profile failures and foreign DAO rejection, visitor/signer restrictions, exact signed payments, the 16-milestone bound, failed/pending drafts, accessibility and horizontal overflow. The existing Decide design cases also passed on both devices (24 cases) after extracting their unchanged API fixture for reuse.

The first new test attempt failed in its invalid synthetic signing-key fixture before reaching the UI. After fixing that fixture, checks exposed a service-heading accessibility issue and numeric ABI decoder transport in the test; those were corrected. A development hot reload closed one desktop dialog while its test was running; the final stable Works run passed all 12 cases. The first full unit run exposed that the existing in-memory Vue renderer lacked style/dialog behavior required by the new tabs; that test caller now implements those browser properties and mocks optional profile reads. Its stale-project assertion now follows the reference rather than the removed title wording. The final full suite passed.

The testnet build, touched-file formatting and whitespace checks passed. The existing large-chunk warning remains. Browser signatures use real disposable vault cryptography with synthetic API/relay responses; this does not establish live funding, review or settlement. Paid/native end-to-end scenarios have been updated for the selectors but were not rerun for this UI change. Testnet publication and actual HTTPS verification are pending.
