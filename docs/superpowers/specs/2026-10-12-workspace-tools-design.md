# Treasury, Documents and Members experience

The user requested improvements to these three remaining workspace tabs. This follows the established search/filter toolbar, large plus and contextual help icons, readable lists and native popup pattern approved for Decide, Works, Payroll and Grants. Implementation proceeds inline under the repository's continuous-session instructions; no new governance, payment or membership policy is introduced.

Treasury has Payments, Your balances and Reports sections. Available, reserved and unwithdrawn claims remain distinct exact balances. Payments can be searched by named recipient/source and filtered by state. Settlement stays on the exact approved obligation; external statements stay explicitly unpaid evidence, inside a contextual popup. Plus opens deposit instructions; Your balances offers a withdrawal popup showing the exact selected balance, destination and amount. Fractional existing claims/stake remain fully withdrawable. Reports retain reconciliation, completeness warnings and full exports. No arbitrary spending or new wallet transfer integration is introduced.

Documents has Library and Constitution & legal sections. The library shows readable public titles/file names, exact latest versions, author labels and public/encrypted state; search and a type filter select loaded records. Details hold inline content, technical identifiers and immutable history. Plus opens Add document, offering file upload or the existing small structured JSON editor. New IDs are generated once per draft, collision checked against loaded document IDs, and retained through retries. Add version selects an existing record by title instead of requesting an ID. Upload verification/publication and interrupted-upload recovery remain intact. Managed document registration selects titles, while exact-version adoption, administrator/member-vote approval, acceptance and history remain intact. Private-access setup is collapsed when healthy and still reachable, with unresolved access shown clearly. Private metadata is never used for public labels.

Members has Directory and Applications sections. Directory keeps cards/list preference, named search and status filters, adds a role filter, and puts plus/help in the same row. Each member has a contextual Manage button for administrators; its popup begins with the selected person's current roles and credits and retains private-access and handover safeguards. Plus opens Add member or Sponsor application according to the existing admission policy. Applications list keeps endorsement/review actions. Applicant public join identity remains an explicit public-only import/paste, with verification before admission; no nonexistent email invitation or identity search is promised. Endorsement documents use title/version choices and renewal starts from the actual application row rather than a raw ID. Joining instructions remain available to visitors and admission-policy controls stay contextual.

Reuse Vue, native dialogs, released producer schemas, existing integer money/document helpers and public profiles. No new dependencies, API or contracts. Dialogs preserve cancelled/failed drafts, disallow edits/escape/close while pending, and clear only on confirmed success. Mobile wrapping, keyboard navigation, accessible labels, foreign DAO isolation and fallback when profile reads fail are required. Commit completed work to dev and publish only the previously authorized testnet frontend after verification.
