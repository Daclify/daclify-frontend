# Grants experience

Approved in chat on 2026-10-12: Rounds and Applications tabs with search/status filters, plus and contextual help in a responsive toolbar; lists below and forms in native accessible dialogs.

Rounds use their exact rules document's readable title, stage, application deadline, lifetime funding limit and cumulative awards. Only active administrators create rounds. The Create grant round popup has Rules, Funding and dates, and Review steps. Rules are selected from published DAO document versions; eligibility is humans, optionally active agents. Funding limits are positive whole native tokens, entered explicitly. Three local date/time deadlines must be strictly ordered and finish within one year. The review explains that creating a round reserves no funds.

Applications show their proposal title, named applicant, exact total and status. Plus opens Apply for a grant with an eligible open round selector. Applicants select a published proposal version, enter 1–16 separate positive whole-token milestone amounts with independent due dates, and a bounded term. Editing preserves every existing date and exact amount; legacy fractional payments require an explicit replacement and are never rounded. Drafts and review acknowledgement survive cancellation/failure; changing terms resets acknowledgement. A separate submit action is explicit consent to the frozen terms.

Administrators review each application in a popup with its immutable terms, an eligibility decision and a published review-record picker. There is no global document-ID panel. Eligible applications open a funding vote using the saved DAO policy; summaries show percentages and human durations. Funding remains a passed/finalized Decide vote whose execution checks caps, backing, identity and code pins. Awards link to Works for delivery and independent milestone review. No new administrator funding bypass.

Document titles/versions come from existing public metadata. Encrypted metadata remains opaque. Document/name failures cannot hide readable module records or permit selecting foreign DAO records. Show retry and a link to Documents in another tab. IDs stay internal except stable fallback labels and optional record references. Step validation, keyboard tabs, native-dialog focus, busy suppression of editing/escape/closing, success-only draft clearing, responsive layouts and accessibility are required.

Implementation choices: reuse Vue 3, the canonical released SDK and existing document/amount helpers; parent owns authenticated execution and independent document/member loading. No new dependencies, API/schema, contracts or funding policy changes. Work inline on dev, preserve other worktrees, push completed frontend changes and publish the verified frontend to the previously authorized testnet only.
