# Installable PWA implementation plan

Execute inline on `dev` under the repository's continuous-session workflow.

**Goal:** Let users install Daclify with a branded icon and launch it as a
standalone app through their browser.

**Design:** Publish a same-origin web app manifest with a stable root identity,
root start URL/scope, standalone display and existing espresso/amber branding.
Provide 192/512px PNG icons, a maskable icon, an Apple touch icon and an SVG
favicon using the app's existing `d.` mark. Link the manifest and Apple metadata
from the shared HTML entry so Vue deep links expose the same app identity.

**Options:** Native browser installation needs only metadata and icons and is the
selected approach. A custom install button would add browser-specific lifecycle
code without being required for installation. Offline service-worker caching
would add update and privacy obligations; the requested app still needs its API
and chain online. No new dependency, cache, background signing or offline actions.
See [MDN's installability guide](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable).

**Scope:** `index.html`, `public/manifest.webmanifest`, `public/icons/`,
`playwright.pwa.config.ts`, `tests/e2e/pwa.spec.ts`, `package.json`, README,
CHANGELOG and `docs/releases/requirements.json`. Preserve root hosting and the
existing SPA redirect. No backend, schema, wallet, authentication or API changes.

## Verification commands

Use the repository's Node 24.21.0/npm 11.19.0 toolchain.
`npm run test:e2e:pwa` builds an isolated production bundle and runs the desktop
and mobile Chromium checks. `npm run verify` covers the repository's required
static/unit checks; `npm run build` verifies the normal production build.

Native OS installation, Safari/iOS, external login in an installed app and the
hosted deployment remain separate manual qualification; local Chromium checks
cannot establish those results. No deployment is authorized by this work.

## Actual evidence

- Before implementation, the Chromium regression failed because the HTML had no
  manifest link. Initial post-implementation assertions exposed CDP normalization:
  Chromium returns `kStandalone` and RGBA colors and omits short-name/icon-purpose
  fields. The test now checks those fields in the raw manifest and verifies
  Chromium's parsed identity, scope, launch mode and installability separately.
- `npm run test:e2e:pwa`: both desktop/mobile Chromium cases passed against an
  isolated production bundle, with zero manifest/installability errors. Every
  manifest PNG and the Apple icon decoded at its declared dimensions. API HTTP
  fixtures serve only the page shell; no live authentication or chain flow was tested.
- `npm run verify`: lint policy, strict Vue/TypeScript and all 155 unit tests in
  32 files passed on Node 24.21.0/npm 11.19.0.
- `npm run build`: the normal production bundle built successfully, including the
  manifest, SVG favicon and all three PNG icons.
- Scoped Prettier checks passed for the HTML, TypeScript, JSON, SVG and this plan;
  `git diff --check` passed. SVG and webmanifest need explicit HTML/JSON parsers.
- Reviewed the rendered 512px icon and the source/diff. Its opaque background and
  centered monogram fit the maskable safe area. No dependencies, backend files,
  signing/session rules, keys or authority configuration changed.

Browser runners emitted the existing `NO_COLOR`/`FORCE_COLOR` environment warning.
The successful PWA run made no requests to a live backend.
