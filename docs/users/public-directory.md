# People and their communities

Users includes public on-chain DAO members, even before they publish a profile. Public cards and list rows show available aliases, proven DAO memberships and the latest recorded successful DAO action. Legacy plaintext profiles may also expose names, avatars, mottos, locations and contact links. Current encrypted personal fields are not returned by the public directory. Open a name to see the profile or select a community badge to open that DAO. Search covers public fields in loaded records; it cannot search encrypted personal fields. Cards/List is remembered in this browser.

Small directories load all memberships automatically. Larger directories load in batches and show Load more users; search, community links and activity cover the memberships loaded so far. If loading fails, the existing results remain available and Retry continues from the failed page.

Matching public native accounts or current signing identities connect memberships across DAOs on the selected runtime. Matching names, email addresses and avatars do not connect people. Distinct native accounts sharing a key stay separate. A member using different unlinked keys may still have separate cards. Private sign-in pairings are excluded from public discovery; this directory does not add a new Hub identity registry.

Last active means the latest successful authenticated member instruction in a DAO, including module actions. It is not an online indicator or sign-in date. Failed actions, enrollment and direct administration do not count. Older activity without a recorded timestamp says DAO activity not recorded. Inactive membership status describes that DAO's membership, separately from activity.

Profiles remain stored with their DAO memberships. The directory selects an available public profile projection while preserving the originals. User details link to all proven loaded memberships and their profiles; only your own records offer editing/account controls. The alias and membership remain public. Current personal fields are encrypted locally and stored on chain; reading them requires the original keys and an explicit recipient grant. Joining a DAO alone grants no personal-profile access. A wallet pairing or sign-in alone does not unlock those keys.

Legacy plaintext profile text, contacts and avatar CIDs remain public, including in chain history after editing or deletion. Encrypting a reference to an already public image does not make the original image private or remove copies. An unavailable avatar falls back to initials. Contact text that cannot form a safe email/Telegram/HTTPS link stays as text. See [account entry and unlocking](account-entry.md) for reading or editing fields shared with you.
