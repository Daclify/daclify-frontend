# Entering Daclify

Start at Account with one of three cards:

- **Login** opens Welcome back. Unlock a vault saved on this device or choose an already paired method: Passkey, Telegram, E-Mail, Telos Zero or Telos EVM. Passkey, Telegram and E-Mail show an icon and the method name. The Telos buttons show their product wordmarks in the portal's amber accent. Back returns to the three cards.
- **New Account** opens New to Daclify? Choose E-Mail, Telegram, Telos Zero or Own Keys under Create with:.
- **Restore Account** opens recovery from an encrypted kit. Supply the kit, its original vault password or separate recovery code, and a new vault password, then select Restore. Cancel returns to the three cards.

Email and Telegram creation require the assisted-recovery checkbox and an available provider. Daclify holds a spare unlocking key in this mode. Telos Zero uses an Anchor proof from your existing native account and pairs a wallet-only Daclify profile; it does not restore signing or private-document keys. Add those separately in Account when needed. Own Keys creates the existing encrypted local vault and requires saving the kit and recovery credential before finishing. An existing saved vault requires replacement acknowledgment and stays intact during quick signup.

When signed in with locked keys, select **Unlock account** in the portal header. This opens Profile's unlock controls directly; successful verification returns you to your previous task. You can also open **Edit profile & account** on your own profile. Use an enabled full-access paired method, or enter **Password for this device** and select **Unlock account** when this browser holds a matching encrypted vault. A wrong password leaves the profile locked. If paired sign-ins do not have full access, **Use another device** opens and focuses the device-approval controls, while **Use recovery kit** opens the existing encrypted-kit form. No email code or device request is sent just by opening these controls. A wallet enabled only for DAO approvals does not unlock private-profile keys.

Private keys stay in browser memory. Clicking, typing, pointer movement and scrolling in a visible portal tab keep unlocked keys active. Keys lock after **12 hours of inactivity**, matching the normal sign-in duration, and also lock when that sign-in expires, when you reload, when you select **Lock keys**, or when you sign out. Activity cannot unlock keys that are already locked. In **Profile**, an account with full-access email recovery can choose **E-Mail**. If exactly one full-access email is paired, its address is filled in; with multiple addresses, enter the one you want to use. Select **Send code** and wait for **Code requested**, then enter the 8-digit code from your inbox and select **Verify code and unlock**. Requesting a code requires your click; it does not happen automatically. No vault password is needed for that method, and the profile editor stays open. A sign-in-only method cannot unlock private fields. **Access & recovery** remains available for an encrypted kit or another supported recovery method. If options cannot be loaded, use **Retry unlock options**. A failed verification or recovery leaves the private fields locked.

Email codes last **10 minutes** and can be used **once**. Requesting another replaces the previous code. Use the latest code requested in the same browser. Once email verification succeeds, its code is cleared even if restoring account access fails; a restoration error is shown separately. Request a new code to verify again. The normal signed-in session lasts **12 hours** from sign-in; it does not slide forward with browsing. A locked key vault or expired session does not block or disable the account.

Back sits in the top-right corner of the Login and New Account cards. The screen blocks Back while an account or wallet request is pending. Returning from Telegram signup resumes the verified ticket in New Account. Your intended destination remains attached to all three journeys.

**Telos DAO** sits directly below Daclify DAO in the sidebar. It opens the separate Telos governance screen, including ballot history retained by the configured chain's contracts. My DAO remains your community list. Testnet records are testnet records; voting requires separately qualified Decide signing configuration and a native wallet approval.
